# Shared Before/After and Repeat-Photo Capture

Implemented October 3, 2026. Physical-device acceptance remains outstanding.

1. **Architecture:** Existing Paving capture, pair storage, pair cards, comparison generation and exports are reused. The existing temporary comparison dialog now also views saved pairs. Optional camera preview is isolated in `public/match-camera.js`.
2. **Files:** `server.js`; `public/app.js`, `match-camera.js`, `help-catalog.js`, `styles.css`, `index.html`, `admin.html`, `install.html`, `sw.js`; three browser/database verification scripts; source-gate tests. Latest main was integrated to preserve concurrent QR, Location Intelligence, Bulk Metadata, Capture Templates, Related Photos internal-comments, Duplicate for New Photo and AI Visual Analysis work.
3. **Schema/API:** No schema changes. Existing `capture_pairs.comparison_opacity` remains the preference field. New authenticated `PATCH /api/pairs/:id` accepts a finite numeric `comparison_opacity` between 0 and 1. Pair ownership is required. Existing create/list/unpair/comparison APIs remain in place. Pair creation retains existing transaction locks and one-pair-per-photo protection.
4. **Concrete:** Client and server both honor the shared Before/After feature gate, including account-level disabling. Pair listing, creation, unpairing, comparison JPEG, repeat capture and shared exports are available.
5. **Editions:** General Pro, Paving, Concrete, Property Manager, HOA Maintenance, General Contractor and Roofer. Basic, Issue Reporter and Road Issue Reporter are excluded. Paving's legacy asphalt identifier is preserved.
6. **Direct workflow:** Take Matching Photo on a saved photo card opens its reference directly. Paired photos explain the membership restriction; unpair before creating another relationship. The Camera Tools entry and Paving Photo Reason entry remain available. Property/HOA reach shared pairing through their existing Photo Library controls in Organize.
7. **Context:** All repeat captures retain topics and an owned job. Concrete retains element and exact subject description (`concrete_location`). Phase and purpose start as editable source suggestions; the user chooses values describing the new photograph. Stage derives from the selected purpose. Legacy stage alone is not copied. Condition becomes `not_assessed`; severity becomes `none`. Notes, titles, measurements, footprints, mix specifications, findings, AI results, status, history, approval and timeline links are not copied. GPS is acquired anew. Property/HOA repeat photos are separate library captures; their existing timelines and asset histories remain intact.
8. **Viewer:** Side by Side and Overlay reuse the common comparison dialog. Overlay places After over Before. Temporary comparisons remain unsaved; saved pairs offer Save Comparison Opacity. Maintenance's naturally derived Before/After can use this viewer without creating a duplicate pair.
9. **Opacity:** Repeat capture saves its reviewed opacity. Existing-photo pairing initially preserves the original side-by-side presentation. Saved viewer can add or update opacity through PATCH without unpairing or changing either original.
10. **Live-camera investigation:** Native file-input camera capture cannot host an HTML ghost guide. HTTPS `getUserMedia` can provide inline preview; camera permissions, facing-mode selection, inline video, lifecycle interruptions and delayed permission responses require explicit handling. Sources: https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia and https://webkit.org/blog/7763/a-closer-look-into-webrtc/ . WebKit PWA camera failures have been reported at https://bugs.webkit.org/show_bug.cgi?id=273938 . These sources establish implementation constraints, not physical-device certification.
11. **Live mode:** Optional Match Camera is exposed on secure desktop and Android browser contexts with `getUserMedia`. It provides a reference-opacity slider and rear/front camera preference, captures only the camera frame as JPEG, then returns to existing post-capture overlay. Camera selection is a preference subject to available hardware. iPhone/iPad remain on native capture because reliable Safari/PWA acceptance has not been established. No browser is claimed physically certified by automated checks.
12. **Fallback:** Native Take After Photo is always available. Unsupported platforms, permission rejection, startup timeout, unavailable preview and failed frame capture retain reference-before-capture, post-capture opacity, retake and save. Use Native Camera and Cancel release the stream. Hiding the page and navigating also release it. Late permission results after cancellation are stopped.
13. **Exports/reports:** Shared PDF/Word exports include both originals with independent notes/details when both members are selected. Saved pairs are recognized independently of Paving edition. Document previews retain Before/After originals. The comparison JPEG endpoint uses saved opacity. Current main deliberately exports original evidence rather than replacing it with a composite. HOA/Property specialist stage-derived reports remain unchanged.
14. **Paving regression:** Automated browser checks cover existing-photo pairing and swap, static reference capture, post-capture overlay, saved opacity, unpair, retry and default capture entry. Database checks cover pair membership, comparison JPEG and PDF/Word output.
15. **Concrete verification:** Browser fixtures verify editable completion phase/purpose, retained element/location and reset assessment fields. Real local upload verifies phase/purpose/stage persistence, account/version-bound idempotent receipt replay, matched pairing, comparison and exports.
16. **Other editions:** All seven eligible editions were checked in Chromium and WebKit at 390 and 1440 pixels. Excluded editions and account-level feature disabling were checked. Property global parity and all-edition Help regressions run separately.
17. **Release:** Deployment status and live verification are recorded in the completion report. Assets use a new shell version so installed apps can refresh.
18. **Physical testing:** Still required on iPhone Safari, installed iPhone PWA, Android browser and installed Android PWA. Check permission allow/deny, rear/front selection where exposed, portrait/landscape, interruptions, low-memory behavior, native fallback, retake, save, reopen and export. Browser fixtures and synthetic camera frames do not establish physical-device behavior.
19. **Limitations:** One pair per photograph; no multi-photo series, scheduling, GPS viewpoint inference, AI change detection or automatic registration. Reference picker lists the first 30 unpaired photos; direct Take Matching Photo bypasses that list. Matching saves require connectivity. Pair retries reuse the saved After photo in the current screen; after navigation use the library's pair builder. Existing timeline/asset relationships are not automatically copied to the new library capture.
20. **Next alignment enhancement:** Add optional manual translate/scale/rotate controls with separately persisted transforms and matching export rendering after physical-device camera acceptance. Original evidence must remain unchanged. Scheduling can call the shared viewer with reference plus new photo; persistent pairing still observes the membership rule.
